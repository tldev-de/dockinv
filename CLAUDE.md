# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

DockInv inventories Docker containers across many hosts and flags end-of-life / vulnerable images
using **Trivy** (CVEs) and **Xeol** (EOL). Two independently-deployed parts that share no code:

- **`agent/`** — a tiny single-file Flask app (`agent.py`) next to each Docker host. Mounts
  `docker.sock` (read-only) and serves `GET /containers`. Auth is a shared secret (`HTTP_TOKEN`,
  compared via `hmac`); it **refuses to start without one** (opt-out `DOCKINV_ALLOW_NO_TOKEN`).
  Runs as root via gunicorn.
- **`server/`** — Flask web app + Celery worker that polls agents, stores results in SQLite, runs
  the scanners, and renders the dashboard. Non-root.

The server is the client and the agent is the server; they talk only over HTTP(S). Agents belong on
a private network.

## Server architecture

App-factory pattern: `create_app()` (`server/app.py`) wires blueprints, extensions
(`extensions.py`: SQLAlchemy, Flask-Migrate, CSRF), CLI groups, optional auth, and security headers.
Celery tasks reuse the Flask app via `ContextTask` (pushes an app context per task).

Three flows:

- **Collect** (`tasks.py::data_collector_background_task`): Celery beat polls each enabled host,
  upserts `Image`/`Container`, deletes stale containers. The only writer of inventory data. Also
  triggerable on demand from the UI (`/hosts/collect` → `.delay()`, which needs `CELERY_BROKER_URL`
  set on the web process).
- **Scan** (`trivy_/xeol_background_task`): runs the `trivy`/`xeol` binaries on stale/unscanned
  images and stores the raw JSON in `Image.status_trivy` / `status_xeol`.
- **Present** (`routes/frontend.py`): server-rendered templates; the per-image views parse the
  stored scanner JSON on the fly.

**Key invariant — keep the vulnerability projection from drifting.** `Image.status_trivy` is the
source of truth; the `Vulnerability` table is a normalized index of it (powering `/vulnerabilities`).
Write a Trivy result *only* through `vulnerabilities.set_trivy_result(image, json)` — it updates the
JSON and rebuilds the rows in one transaction. `flask vulns verify` fails on drift; `flask vulns
rebuild` backfills/repairs.

Data model (`models/`, `@dataclass` + `BaseModel`): `Host 1—N Container N—1 Image 1—N Vulnerability`.
`BaseModel.save()/delete()` commit with rollback-on-error and return `None` on failure (callers
check this). Deletes cascade (host→containers, image→vulnerabilities). `Image.repo_digest` is the
image's natural key.

**Auth** (`auth.py`): optional OIDC — a `before_request` login guard is installed only when all of
`OIDC_DISCOVERY_URL` / `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` are set; otherwise the UI is
unauthenticated (startup warning). `/health` and static assets stay public.

**Frontend**: Jinja + Tailwind/DaisyUI (compiled at build time) + **HTMX** (vendored under
`static/js/`). All JS lives in external files and row clicks use `data-href` — no inline scripts or
handlers, so a strict CSP (`script-src 'self'`, set in `register_security_headers`) applies. Keep it
that way.

## Commands

Run Flask commands from `server/` with it on `PYTHONPATH` (the image sets `PYTHONPATH=/app`); config
comes from env vars (`config.py`).

```bash
docker compose -f docker-compose-dev.yml up [--build]   # server :8000, agent :9999, redis, worker
```
Code is bind-mounted and Flask auto-reloads, but **restart the Celery worker manually** after
editing `tasks.py`. The dev compose auto-migrates and registers a dev agent.

```bash
flask hosts ls|add|edit|rm        # manage the agents the server polls
flask images ls | containers ls
flask vulns ls|verify|rebuild     # CVE index: list / drift-check / rebuild from JSON
flask db upgrade                  # apply migrations
flask db migrate -m "..."         # after a model change — commit the generated version file
```

Tests (separate from the dev loop):
```bash
cd server && PYTHONPATH=. pytest       # unit/integration   (requirements-dev.txt)
cd server && PYTHONPATH=. pytest e2e   # Playwright browser (requirements-e2e.txt + a browser)
cd agent  && PYTHONPATH=. pytest
```
CI runs all three (`.github/workflows/test.yml`); images build and publish on push/release
(`build.yml`).

## Gotchas

- Any model change needs a migration (`flask db migrate`, commit the file).
- The agent is standalone — no shared code or deps with the server; keep it minimal.
- `SECRET_KEY` must be set in production, else `create_app` uses an ephemeral key and sessions break
  across workers/restarts.
- `static/css/theme.css` is generated by Tailwind and gitignored — never edit it by hand.
